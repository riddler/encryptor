### **Breaking**

- The wire format moves to v2 (ADR-0009 Amendment A): every string the package writes that named the key's owner now says scope. The context key `"tenant_ref"` is now `"scope_ref"`; the key name `"t/<ref>/v<n>"` is now `"s/<ref>/v<n>"`; the wrapping-context key `"encryptor-tenant-ref"` is now `"encryptor-scope-ref"`; the wrap purpose `"tenant-key-wrap"` is now `"scope-key-wrap"`; the default namespace `"encryptor-tenant"` is now `"encryptor-scope"`, in `Encryptor.Envelope` and in `Encryptor.Provider.GcpKms`; the root purpose `"tenant-ref"` is now `"scope-ref"`; its HKDF label `"encryptor/v1/tenant-ref"` is now `"encryptor/v1/scope-ref"`; and the Cloud KMS provider's default `:key_id_prefix` `"t-"` is now `"s-"`, which changes every default `CryptoKey` id. Every string above is now a pinned constant: respelling any of them again means re-encrypting every ciphertext and wrapped key written under the old spelling, not a key rotation.
- Nothing written by 0.6.x or earlier opens under 0.7.0: a wrapped key it wrote does not unwrap, a ciphertext it wrote does not decrypt, and there is no fallback read and no migration helper. A host with nothing stored upgrades by changing its dependency; a host holding rows written by 0.6.x or earlier stays on 0.6.x, because re-encrypting them under 0.7.0 needs a v1 read path this package does not ship.
- Pass `"scope-ref"` to `Encryptor.Envelope.root_subkey/2` where you passed `"tenant-ref"`: the reference subkey, and with it every scope reference, is derived under the new label. `Encryptor.Envelope.subkey/2` refuses `"root-wrap"`, `"scope-ref"` and the retired `"tenant-ref"`.
- `"tenant_ref"` stays a reserved context key on both vault profiles, beside `"scope_ref"`, so a caller sending it gets `{:reserved_context_key, "tenant_ref"}`; `"scope_id"` and `"tenant_id"` stay reserved on a `:scoped` vault.
- A KMS key policy, audit query or support tool that reads the `"tenant_ref"` encryption-context key, or a deployment that names Cloud KMS keys by the old `"t-"` ids, must change to the v2 spelling; a deployment that must keep naming an existing `CryptoKey` passes `namespace: "encryptor-tenant"` and `key_id_prefix: "t-"`, but wrappings written under v1 bindings in it still do not unwrap.
