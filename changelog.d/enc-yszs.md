### Fixed

- `inspect/2` of an `Encryptor.Error` no longer renders the `:engine` term or the detail of `{:invalid_config, key, detail}` and `{:invalid_key_descriptor, detail}`, so wherever such an error is printed - a log line, a crash report, a supervisor's report of a vault that refused to start - it no longer shows a provider's own failure term, which may hold key material. The error renders as `#Encryptor.Error<...>` with those values shown as `"[redacted]"`; the struct's fields are unchanged, and code that needs the term still reads `error.engine`.
- A provider's `{:unknown_key, _}` or `{:key_unavailable, _}` answer now reaches the caller as `{:unknown_key, selector}` or `{:key_unavailable, selector}` with the selector the vault asked about, rather than whatever the provider put beside the tag, which `Exception.message/1` rendered. A provider answer of `{:provider_not_started, _}`, `{:missing_optional_dependency, _}` or `{:not_provisionable, _}` whose second element is not an atom is now `{:invalid_key_descriptor, :provider_off_contract}`, and an `init/1` failure of `{:missing_config, _}` that is not a list of atoms, `{:invalid_config, _, _}` with a key that is not an atom, or `{:missing_optional_dependency, _}` with a name that is not an atom is now `{:invalid_config, :provider, :init}`, each with the provider's term in `:engine`.
